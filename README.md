# ASCII layout review workbook

ASCII art is easy to preview and surprisingly easy to damage when you move it somewhere else. A face that looks balanced in an editor can become a staircase in a message. A carefully shaded silhouette may disappear against a different background. This guide treats character art as a small layout project: choose a useful source, simplify it, inspect the grid, and test the actual destination before sharing it. The goal is a readable result, not the largest possible collection of symbols.

## Start with the destination, not the source image

Decide where the finished piece will appear before choosing a resolution. A terminal banner, a narrow chat message, and a printed worksheet impose different limits. Count the approximate columns you can use in that destination. If the receiving editor supports a code block, use one for a first test. If it only offers proportional text, consider exporting a picture instead. A character grid depends on consistent cell spacing; it cannot repair a host application that collapses spaces or substitutes a proportional font.

Make a tiny transfer test before spending time on the artwork. Put two vertical edges on separate lines and add a few spaces between them. Copy those lines to the destination, then reopen or preview the saved version. Check both desktop and mobile if both matter. This simple experiment exposes whitespace collapsing, automatic wrapping, and font substitutions early. Do not assume that a successful paste into one text box means the final published page will preserve the same layout.

## Pick an image with a strong silhouette

A clean outline usually matters more than photographic detail. Choose one subject against a relatively quiet background. A high contrast flower, a cup, or a side profile gives the conversion a clear structure. A crowded street photograph asks a small grid to represent far too many edges at once. Crop before increasing the number of columns. Removing an irrelevant background often improves recognition more than trying another dense character ramp.

Use a source you own or have permission to adapt. Consider whether the picture contains names, faces, screens, or location details you did not intend to share. Character conversion is not a reliable anonymization method. A recognizable outline or text in a photograph can remain identifiable after stylization. Work with a non-sensitive sample while learning the controls, and review the final result with the same care you would apply to an ordinary image export.

## Establish a small, readable baseline

Start with a modest grid so that you can see the entire composition at once. Look for the largest light and dark regions first. Can you identify the subject without reading a caption? Are important gaps still open? If not, simplify the crop or adjust the overall contrast before touching individual cells. Tiny details cannot compensate for a silhouette that no longer makes sense.

Characters have different visual weights. A period suggests a light mark; a dense cluster of strokes appears darker. Their exact appearance depends on the font. Compare the result in the font and background you expect readers to use. A ramp that reads smoothly on a bright background may feel reversed or excessively heavy in a dark terminal. Keep one baseline version unchanged so that you can compare later adjustments rather than relying on memory.

## Preserve proportions deliberately

A text cell is often taller than it is wide. Treating a square image pixel as a square character cell can make a face unusually tall or a circle look narrow. Judge proportions in the actual display, not only in the numerical grid dimensions. If the tool offers aspect or scale controls, adjust one at a time. If it does not, try a different grid size and compare the full outline again.

Avoid fixing proportions through random spaces inside the subject. Those spaces also change shading and may introduce confusing holes. Decide whether the problem is global, such as a stretched silhouette, or local, such as one jagged edge. Global problems belong in the conversion settings or crop. Local problems may benefit from a small manual edit. Separating those two cases keeps a quick refinement session from becoming an endless repainting exercise.

## Make manual changes with a specific purpose

Give each edit a job. You might reopen a gap between two shapes, remove an isolated speck, or strengthen the edge of a letter. Change a small area, step back, and compare it with the baseline. If you cannot explain what improved, undo the change. This is especially useful for portraits, where an apparently harmless extra mark can change the expression or create a distracting feature.

Do not smooth every irregularity automatically. Some uneven edges make a character drawing lively, while others hide its subject. Evaluate the whole composition at its intended viewing size. Zooming in encourages edits that are invisible or counterproductive when the piece is small. Stop when the essential shapes are clear and the destination test passes. More manual work is not automatically a better result.

## Audit the text before the final paste

For strict ASCII output, distinguish ordinary spaces from tabs and ordinary printable characters from Unicode symbols. A tab can occupy a different width in another editor. A decorative Unicode block may look attractive but is not part of the basic ASCII range. Neither is inherently wrong; the important point is to know what your chosen destination accepts. Do not silently replace characters in the only copy of your artwork.

This workbook is documentation only. It provides no executable validator, hosted conversion service or automated display-width test. If you inspect a text file, report tabs, non-ASCII characters and control characters without silently changing the only copy. Visual review in the destination remains necessary.



## Keep a reproducible final version

Record the chosen crop, approximate grid size, display font, and export format in a short note next to the finished file. Use descriptive filenames rather than repeatedly overwriting a file called final. A text export preserves editable characters; an image export preserves a particular visual presentation. Keep both when you need future edits and dependable display. Neither format guarantees that another platform will retain every detail unchanged.

Finish by inspecting the saved result where it will actually be seen. Check the first and last lines, blank rows, any long line that might wrap, and whether background contrast still works. Ask whether the subject reads at ordinary viewing distance. If the destination cannot preserve a text grid, use an image rather than compensating with fragile spacing tricks. A small, recognizable piece that transfers reliably is more useful than a large, elaborate one that breaks on arrival.

## Manual review sheet

Create one review note for each destination rather than assuming that a successful paste covers every application. The fields below describe what to record. They are a manual worksheet, not a tested software interface or a claim that every destination supports the same controls. Keep examples synthetic and avoid personal photographs when explaining a formatting problem to someone else.

**Purpose:** Describe what a reader should recognize. A small flower silhouette, a short greeting and a shaded portrait have different success criteria. Write a plain description before choosing the number of columns so that later decisions have a clear reference.

**Source and permission:** Record a local reference name and whether it is an owned or permitted sample. Do not put private source images, personal contact details or confidential file paths into a public review note. A public worksheet can state that permission was checked without exposing someone else's information.

**Destination conditions:** Note the application, approximate available width, font choice and whether the content is a code block, plain text or an image. Capture the result after saving or reopening the destination. An editor view and its final display may behave differently.

**Observed differences:** Separate a wrapped line, collapsed spaces, a substituted font and a change in contrast. These are different problems with different remedies. State what you saw rather than guessing a hidden browser or platform cause.

**Decision:** Keep the text version, simplify the drawing, choose an image export or postpone sharing. Record why that choice serves the original purpose. A failed transfer test is useful information; it is not a reason to keep pasting the same broken layout and hope that it changes.

## Sharing a useful reproduction

When asking for help, include a small non-sensitive sample and the expected shape in words. Report the destination conditions and the first step where the appearance changes. Keep the original version unchanged so that another reviewer can compare the same starting point. This workbook does not grant rights to other people's images or promise that a particular font or export will work everywhere.
